⚽ Changelog — Kitly

v6.15.0 — 2026-11-16 — „Anzeigetafel“

  • A progress bar replaces the plain "Loading data" text. Below the bouncing ball the overlay now shows the current step ("Step 2 of 3: Categories"), a bar, a detail line (which title search or category, how many files so far, "n of total" while upload dates are checked) and the time elapsed.
  • Estimated time left. Calculated from elapsed time and progress, shown from about 10 % onwards and rounded to 5 seconds; before that the overlay says it is still estimating. It is an estimate, not a measurement: the five title searches have no fixed number of pages (each stops once a page holds nothing new), so the figure can jump early on. The bar is a weighted share across the steps of the chosen source (Commons search, PetScan, or both).
  • Cancel button. Stops the retrieval at once, including a request still in flight or waiting after a rate limit, and leaves the list from the previous retrieval untouched: no error message, no notification, and the "since last visit" day is not updated. Background work such as the usage scan is not affected.
  • Keyboard: focus moves to the Cancel button while the overlay is open and returns to where it was afterwards. Screen readers announce the step line.
  • Internal: the shared API helper accepts an optional abort signal, and the error handlers that swallow a failure to keep a partial result now let a cancellation through.

v6.14.0 — 2026-09-14 — „Nachspielzeit“

  • Colours are cached per file version, not per filename. Replacing a file on Commons with a corrected version left the old colour in place until local storage was cleared. The key now carries the upload timestamp. The previous colour cache (kitColorCache_v1) is removed on first start of this version: it is a pure derived cache, holds nothing you entered, and is rebuilt within seconds. Nothing else in local storage is touched.
  • The usage scan reads its own cache. It has been writing it since v6.13.0 but never reading it, so every reload fetched everything again even though the data is valid for 24 hours. A second run over the same files now costs no requests at all.
  • The first-upload date of files with more than 50 versions was wrong. A batch query returns at most 50 versions per file and gives no continuation marker, so the oldest version returned was mistaken for the original upload. Affected files are fetched individually now, which matters for the "hide file updates" filter: those files were classified as new uploads.
  • The category walk stops at the limit. Each of the eight kit categories used to page through up to 10,000 entries even when the limit was 100. It now stops once the limit is reached; a category is ordered by the time entries were filed, newest first, so what drops out was filed after the limit's worth of other entries in the same category.
  • A batch whose usage list ran into the API budget is split fully. Until now only files that came back empty were re-fetched. The file at which the budget ran out gets a truncated list rather than an empty one and was waved through as complete. Splitting also goes deep enough to reach individual files, so their result is cached instead of being fetched afresh every time.
  • Fix: long goalkeeper socks (gkhl, gkal, gktl) were not recognised as long, so they showed up alongside the short ones instead of replacing them.
  • Fix: .tif, .tiff and .webp were missing from the filename analysis and from the pattern token of the infobox code, so the extension stayed in the name and broke kit-type and season detection for those files.
  • Fix: clicking "Fetch data" twice no longer starts a second retrieval alongside the first, where whichever finished last won regardless of the filters it started with.
  • Fix: the PetScan query passed the namespace as ns=1, which is not a valid parameter and was ignored. It is ns[6]=1 now. Checked live: the result is identical either way, because the kit categories contain practically nothing but files.
  • The statistics line says "completed in total" for the tick counts; they cover everything you have ever ticked, not just the current view.

v6.13.2 — 2026-09-14 — Bug fix

  • Fix: the error message from a failed retrieval was overwritten immediately. Since v6.13.1 the redraw ran after the message was set, so all that remained on screen was „No teams found“ instead of the reason. Introduced in v6.13.1, fixed here.
  • Fix: the post-render timer existed twice. The wrapper from v5.2 survived alongside the shared timer introduced in v6.13.1, so every redraw scheduled two passes. The wrapper is gone; the five call sites schedule the pass themselves. Introduced in v6.13.1, fixed here.
  • Fix: the season filter no longer narrows its own list of options. Picking a season used to remove every other season from the dropdown, so getting back required resetting the filter.
  • Fix: numbering in the generated infobox code. Kit parts with a fixed number could collide with automatically numbered ones, which produced two kits sharing a number.
  • Fix: a failed colour analysis is no longer cached. Until now a single failed image load stored an empty colour for that file for the rest of the session.
  • Fix: the kit-set heading no longer runs underneath the tick button, and in light mode links in the card header keep a readable hover colour.
  • Accessibility: the tick buttons carry a label and the checkbox role in every view, the three dialogs announce themselves as dialogs, keep the focus inside while open and hand it back on close, and the version badge is a real button reachable by keyboard.
  • Internal: retries and error handling for all API calls now sit in one place, dead code and 15 unused translation keys removed, several stale comments corrected.

v6.13.1 — 2026-09-14 — Bug fix

  • Fix: usage figures were wrong and stayed wrong. The usage query asks for up to 500 entries, but that budget applies per request, not per file. A single heavily used file (File:Kit body.svg has tens of thousands of usages) consumed the whole budget, and every file behind it in the same batch came back with nothing. Kitly then cached that nothing for 24 hours. It now follows the API's continuation, splits a batch that runs into the budget, and caches a file only once its list is provably complete.
  • The usage cache key moves to usage_v3_; the old entries are dropped rather than reused, because they may hold exactly the incomplete data described above. Nothing else in local storage is touched, and no completion data is affected.
  • Fix: a failing part of the retrieval no longer discards the rest. If one of the five title searches, the category walk or one of the two sources fails, Kitly keeps what the others delivered and says how much is missing. API errors that Commons returns with HTTP 200 and an error body are now recognised as errors, and only genuinely retryable failures (429, 5xx, network) are retried; Retry-After is respected.
  • Fix: ticks no longer get lost through the spelling of a filename. Commons treats Kit body x.png and Kit_body_x.png as the same file; Kitly stored them as two keys, so a tick set in one view could be invisible in another. Both spellings are now read, and unticking clears every variant. Stored data is left untouched.
  • The „Depth“ field is gone from the interface. The PetScan category crawl always runs at maximum depth now. The setting had no useful case: the kit-template category tree was already covered in full, so any lower value could only lose hits. The functionality itself is unchanged.
  • Fix: an unparseable date no longer sinks a kit set to the bottom of the list. Invalid dates are ignored for the "newest" date and for sorting.
  • Fix: a season written two ways in filenames (16 and 2016) produced two groups under one and the same heading. Both land in the same season group now; genuine spans such as 1617 stay separate.
  • Fix: loosening a filter after a usage scan re-scans the files that were not covered before, instead of showing them with an empty usage list.
  • Fix: a refresh started while a usage scan is still running no longer lets the old scan write its results into the new list.
  • Fix: if a retrieval fails, the list from the previous retrieval is cleared instead of staying on screen underneath the error message.
  • Fix: if the browser refuses the automatic copy of the infobox code (Safari, after the colour analysis), the code now appears in a dialog ready to be copied by hand, instead of only in the console.
  • Fix: in the retrieval panel the data source and the limit sat lower than the date field, because the whole row was aligned to the bottom edge of the „Since last visit“ button. The three fields line up again now, with the button below the date. That button also carried its dark-mode surface into light mode, where it appeared as a grey block with white text.
  • Fix: the hover colour of the view toggle no longer turns the label white on a light background; the tooltips of two filter labels are translated as well.
  • Internal: one shared post-render timer instead of one per render, and filenames containing quotation marks are escaped consistently in the generated markup.

v6.13.0 — 2026-09-14 — „Flügelspiel“

  • New: a third data source, Both (Commons + PetScan). It runs the Commons search first, then adds everything PetScan knows on top and merges the two by filename. If PetScan fails or is unreachable, the Commons result is still shown, with a note.
  • New: the Commons source no longer relies on the title alone. On top of the five title searches it now walks the kit categories live via the Commons API (categorymembers, newest first, bounded by the chosen date), so files whose name breaks the usual scheme are found as well – without the Toolforge replica. Note: brand-new uploads are often not categorised at all yet, so the title search still carries most of the load.
  • New: a „Since last visit“ button below the date field. Kitly remembers the day of your last successful retrieval and sets the date to it on one click. The button only appears when there is something to jump back to.
  • The usage cache is now bounded: one key per file instead of up to three spellings, at most 400 entries, oldest pruned first. If local storage runs out anyway, Kitly says so visibly instead of failing silently.
  • Fix: in the Kit sets view, a kit set containing both short and long socks now shows only the long ones, the same way the Teams view has always done.
  • Fix: switching the language now also relabels the Season and Kit type dropdowns instead of leaving them in the previous language.
  • Fix: the changelog and usage dialogs used two undefined colour variables, which could leave white text on a white background in light mode.
  • Fix: a ticked team button showed two check marks, and it ignored the theme setting in dark mode because it read the operating-system preference directly.
  • Fix: the filter panel could cut off its content on short windows; it now scrolls.
  • Internal: filename analysis is cached per retrieval instead of running repeatedly for the same file, and reading the controls no longer changes the date field as a side effect.

v6.12.1 — 2026-09-14 — Bug fix

  • Fix: the file meta line showed undefined Bytes for the Commons source, which does not deliver a file size the way PetScan does. The size now comes from the imageinfo query and is left out entirely when it is unknown.
  • Fix: the limit warning fired almost every time with the Commons source. It compared the number of search hits scanned against the limit instead of the number of files actually kept.

v6.12.0 — 2026-09-14 — „Doppelpass“

  • New: selectable data source under „Data retrieval“. Commons search (live) is the new default and queries the Commons API directly, so it always sees today's uploads. PetScan (categories) is still available and still finds kit parts whose filename breaks the usual scheme, but it reads a Toolforge database replica: while that replica lags, PetScan returns nothing for the most recent days, which is why Kitly appeared to stop finding new kits. The Commons source matches on the title (Kit body/shorts/socks/left arm/right arm) and therefore reports new files reliably, new versions of older files only incidentally.
  • New: a warning when the source looks stale. If the newest hit is more than a day behind, Kitly now says so instead of just showing an empty list.
  • Fix: ticking a team no longer hides its future kits. The team tick was stored under the club name alone, without a season, so once „Chelsea“ was ticked every Chelsea kit of every later season stayed hidden, including files that did not exist at the time. Team state is now derived from its kit sets.
  • Fix: a tick in the Teams view and in the Kit sets view is now the same tick. The two views used different key formats for the same kit set.
  • New: a ticked kit set reopens when a new part appears, and a ticked file reopens when a new version is uploaded.
  • Data migration: completion data moves from kitStorage_v5 to kitStorage_v6 on first start. Kit-set and file ticks are carried over, team ticks are dissolved into their files. Nothing is deleted; the previous state is kept under kitStorage_v5_backup and the result is reported once in the header.
  • Robustness: Commons API calls now retry with backoff on HTTP 429/5xx instead of silently losing part of the result.

v6.11.1 — 2026-09-01 — Bug fix

  • Fix: the second Copa Libertadores spelling with a _wc_la suffix, e.g. Kit_body_corinthians13H_wc_la.png, is now parsed correctly – team „Corinthians“, season „2013“, type „Copa Libertadores home“ – instead of team „Corinthians13H_wc“ with no season. Role H/A/T optional (defaults to home).
  • New: a warning when the result limit is reached. If PetScan returns exactly as many hits as the limit allows, further files in the period were silently cut off – Kitly now says so and suggests raising the limit or narrowing the date range.

v6.11.0 — 2026-08-31 — Search notifications

  • New: optional notification when a refresh finishes. Enable it with the 🔔 button in the header. Where the browser allows it you get a real desktop notification; as a permission-free fallback that works everywhere (including local file:// and other tabs) the browser-tab title flashes „✅ Kitly“ until you return. Reports how many new kit files were found.
  • Polish: the „Loading data…“ overlay now has a small animation – a bouncing, rolling football with animated dots.

v6.10.3 — 2026-08-31 — Transparent kit type

  • New: the tr kit-type suffix, e.g. Kit_body_kashima26tr.png, is now labelled „Transparent“ (team „Kashima“, season „2026“) instead of the raw code „tr“.
